# Agent hook examples

Labeled examples generated by `scaffold_docs.py --hooks --tool <tool>` for
`docs/use_cases/`. Each JSON block is the exact file setup generates for an
empty project. Review the plan for the repository before approval; see
`agent-hooks.md`.

## Contents

- Claude Code
- Codex CLI
- Antigravity CLI
- Kiro (CLI V3 and IDE 1.x)
- Other tools

## Claude Code

File: `.claude/settings.json`, committed. Generated `if` rules use the project's
recognized use case folder; in the other tools, the gate filters paths.

```json
{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "startup|resume",
        "hooks": [
          {
            "type": "command",
            "command": "cd \"$(git rev-parse --show-toplevel)\" && if [ -f tools/specs/hook_gate.py ]; then python3 tools/specs/hook_gate.py session-start --emit claude; fi"
          }
        ]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Edit",
        "hooks": [
          {
            "type": "command",
            "command": "cd \"$(git rev-parse --show-toplevel)\" && if [ -f tools/specs/hook_gate.py ]; then python3 tools/specs/hook_gate.py after-edit --emit claude; fi",
            "if": "Edit(docs/use_cases/**)"
          }
        ]
      },
      {
        "matcher": "Write",
        "hooks": [
          {
            "type": "command",
            "command": "cd \"$(git rev-parse --show-toplevel)\" && if [ -f tools/specs/hook_gate.py ]; then python3 tools/specs/hook_gate.py after-edit --emit claude; fi",
            "if": "Write(docs/use_cases/**)"
          }
        ]
      }
    ],
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "cd \"$(git rev-parse --show-toplevel)\" && if [ -f tools/specs/hook_gate.py ]; then python3 tools/specs/hook_gate.py before-stop --emit claude; fi"
          }
        ]
      }
    ],
    "UserPromptSubmit": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "{ root=\"$(git rev-parse --show-toplevel 2>/dev/null)\" && cd \"$root\" && [ -f tools/specs/hook_gate.py ] && python3 tools/specs/hook_gate.py turn-start --emit claude; } 2>/dev/null || exit 0",
            "timeout": 8
          }
        ]
      }
    ]
  }
}
```

- After-edit feedback: agent.
- Stop keeps the agent working: yes.
- Warning channel: yes.
- Proof: Claude Code 2.1.307.

The three 1.1.0 moments were seen firing on Claude Code 2.1.307 on 2026-10-21, headless: session state
reached the agent as context, the after-edit block reached the agent, and the
stop blocked twice before the give-up let the agent stop. In the 1.1.0 trial a spec-only stop
warned through `systemMessage`; whether the person sees it was not observable
headless, and the interactive trust dialog was not exercised.

Contract read against Claude Code 2.1.306. The generated Edit and Write
entries both narrow to the use case folder. Warnings reach the person through
`systemMessage`; trust approval belongs to the person.

Turn-start entry: **not yet proven**. `UserPromptSubmit` receives the open-work
list with exit 0, using additional context in Claude Code and Codex, plain
stdout below 3,000 characters in Kiro. Its eight-second timeout includes the
gate's computation cap, stdin and startup overhead. Failures produce no output.

## Codex CLI

File: `.codex/hooks.json`, committed.

Hooks run in the user's login shell (`$SHELL -lc`). Startup files that print
to stdout can corrupt the hook's JSON. Check them during proof; keep hook
startup output quiet.

```json
{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "^(startup|resume)$",
        "hooks": [
          {
            "type": "command",
            "command": "cd \"$(git rev-parse --show-toplevel)\" && if [ -f tools/specs/hook_gate.py ]; then python3 tools/specs/hook_gate.py session-start --emit codex; fi"
          }
        ]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "^(apply_patch|Edit|Write)$",
        "hooks": [
          {
            "type": "command",
            "command": "cd \"$(git rev-parse --show-toplevel)\" && if [ -f tools/specs/hook_gate.py ]; then python3 tools/specs/hook_gate.py after-edit --emit codex; fi"
          }
        ]
      }
    ],
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "cd \"$(git rev-parse --show-toplevel)\" && if [ -f tools/specs/hook_gate.py ]; then python3 tools/specs/hook_gate.py before-stop --emit codex; fi"
          }
        ]
      }
    ],
    "UserPromptSubmit": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "{ root=\"$(git rev-parse --show-toplevel 2>/dev/null)\" && cd \"$root\" && [ -f tools/specs/hook_gate.py ] && python3 tools/specs/hook_gate.py turn-start --emit codex; } 2>/dev/null || exit 0",
            "timeout": 8
          }
        ]
      }
    ]
  }
}
```

- After-edit feedback: agent.
- Stop keeps the agent working: yes.
- Warning channel: yes.
- Proof: Codex 0.159.2.

The three 1.1.0 moments were seen firing on Codex 0.159.2 on 2026-10-21 (`codex exec`): session state
reached the agent as context, the after-edit block on an `apply_patch` edit
reached the agent, and the stop blocked twice before the give-up let the
agent stop; a spec-only stop warned. The login shell printed nothing that
broke the JSON.

Project hooks run only after the person trusts the folder and approves each
hook in an interactive `codex` session. Before that, `codex exec` silently
skips them and logs nothing.

Contract read against Codex CLI 0.163.0. Edits can arrive as `apply_patch`;
the gate reads file names from its patch input. Hooks require the person's
trust, renewed when the hook changes. Codex runs hooks in a login shell
(`$SHELL -lc`): startup files that print can break the JSON. Check this in
proof. The profile keeps blocking on `stop_hook_active`; the shared loop
guard ends repeated attempts.

Turn-start entry: **not yet proven**. `UserPromptSubmit` receives the open-work
list with exit 0, using additional context in Claude Code and Codex, plain
stdout below 3,000 characters in Kiro. Its eight-second timeout includes the
gate's computation cap, stdin and startup overhead. Failures produce no output.

## Antigravity CLI

File: `.agents/hooks.json`, committed.

```json
{
  "up-session-state": {
    "SessionStart": [
      {
        "type": "command",
        "command": "cd \"$(git rev-parse --show-toplevel)\" && if [ -f tools/specs/hook_gate.py ]; then python3 tools/specs/hook_gate.py session-start --emit antigravity; fi"
      }
    ]
  },
  "up-finish-check": {
    "Stop": [
      {
        "type": "command",
        "command": "cd \"$(git rev-parse --show-toplevel)\" && if [ -f tools/specs/hook_gate.py ]; then python3 tools/specs/hook_gate.py before-stop --emit antigravity; fi"
      }
    ]
  }
}
```

- After-edit feedback: nobody.
- Stop keeps the agent working: yes.
- Warning channel: no.
- Proof: Antigravity CLI 1.4.4.

The three 1.1.0 moments were seen firing on Antigravity CLI 1.4.4 on 2026-10-21: session state reached
the agent, and the stop blocked twice, reaching the agent, before the give-up
let it stop. An after-edit hook fired only with a hand-edited matcher, and
nothing reached the agent.

After-edit is not wired. On 1.4.4 nothing reached the agent; per the tool's
1.4.3 changelog the failure is only logged and the tool keeps its result. The
stop checks only the session's Status claims for evidence. Open work arrives at
session start only. No warning channel is documented. Prove desktop workspace
hooks separately from the CLI.

No start-of-turn event exists. `PreInvocation` runs before every model call,
so it is not wired as a per-prompt event. Open work arrives at session start only.

## Kiro (CLI V3 and IDE 1.x)

File: `.kiro/hooks/upspec.json`, committed.

```json
{
  "version": "v1",
  "hooks": [
    {
      "name": "up-session-state",
      "trigger": "SessionStart",
      "enabled": true,
      "timeout": 60,
      "action": {
        "type": "command",
        "command": "{ root=\"$(git rev-parse --show-toplevel)\" && cd \"$root\" && [ -f tools/specs/hook_gate.py ] && python3 tools/specs/hook_gate.py session-start --emit kiro; } || exit 3"
      }
    },
    {
      "name": "up-specification-check",
      "trigger": "PostToolUse",
      "enabled": true,
      "timeout": 60,
      "action": {
        "type": "command",
        "command": "{ root=\"$(git rev-parse --show-toplevel)\" && cd \"$root\" && [ -f tools/specs/hook_gate.py ] && python3 tools/specs/hook_gate.py after-edit --emit kiro; } || exit 3"
      },
      "matcher": "write"
    },
    {
      "name": "up-finish-check",
      "trigger": "Stop",
      "enabled": true,
      "timeout": 120,
      "action": {
        "type": "command",
        "command": "{ root=\"$(git rev-parse --show-toplevel)\" && cd \"$root\" && [ -f tools/specs/hook_gate.py ] && python3 tools/specs/hook_gate.py before-stop --emit kiro; } || exit 3"
      }
    },
    {
      "name": "up-open-work",
      "trigger": "UserPromptSubmit",
      "enabled": true,
      "timeout": 8,
      "action": {
        "type": "command",
        "command": "{ root=\"$(git rev-parse --show-toplevel 2>/dev/null)\" && cd \"$root\" && [ -f tools/specs/hook_gate.py ] && python3 tools/specs/hook_gate.py turn-start --emit kiro; } 2>/dev/null || exit 0"
      }
    }
  ]
}
```

- After-edit feedback: person.
- Stop keeps the agent working: yes.
- Warning channel: yes.
- Proof: Kiro CLI 2.33.1 (V3 engine).

The three 1.1.0 moments were seen firing on Kiro CLI 2.33.1 with the V3 engine on 2026-10-21: session
state reached the agent, the stop block reached the agent and the give-up
was delivered once, and the after-edit result reached neither the agent nor,
in `--no-interactive` mode, the person.

- **The V3 engine is needed.** The default engine ignores `.kiro/hooks/`;
  set `kiro-cli settings chat.agentEngine v3`, or start with
  `kiro-cli chat --v3`. Setup changes no Kiro setting.
- **One block per prompt.** A Stop block is honored once per prompt; the
  next block comes with the next prompt.
- **After-edit warnings** were not shown in `--no-interactive` mode;
  whether the interactive interface shows them is not proven.
- **Trusting tools.** The V3 tool ids are `read_file`, `str_replace`,
  `fs_write` and `fs_append`; the names `fs_read`, `read` and `write` do
  not cover them.

Contract read against Kiro CLI 2.33 with the V3 engine and IDE 1.x
documentation. After-edit warnings never reach the agent; by Kiro's
documentation they reach the person, unproven in the TUI. The documented
warning channel exists at session start and after an edit; at the stop,
ordinary warnings reach nobody. The gate therefore uses one final block for
the give-up instruction, asking the agent to report and stop. Kiro never
receives exit 1 from these commands: it means continue at Stop. The wrapper
turns invocation failures into exit 3, including a missing gate.

CLI V3 supports stop blocking; the IDE documentation says it cannot block,
so prove the actual runtime. File-trigger paths arrive on stdin as
`file_path`; `{{filePath}}` is not substituted. The generated example uses
PostToolUse with `write`; the hook file's location and its `timeout` field
were accepted in the proof.

Turn-start entry: **not yet proven**. `UserPromptSubmit` receives the open-work
list with exit 0, using additional context in Claude Code and Codex, plain
stdout below 3,000 characters in Kiro. Its eight-second timeout includes the
gate's computation cap, stdin and startup overhead. Failures produce no output.

## Other tools

These contracts were surveyed; none has a generated upspec profile yet:

- **Gemini CLI:** `.gemini/settings.json`, SessionStart, AfterTool and
  AfterAgent. JSON `additionalContext` supplies context; `decision: deny`
  with a reason can keep the agent working. Timeouts use milliseconds, and
  exit 3 with text can block, so raw results need translation.
- **Copilot CLI:** sessionStart, postToolUse and agentStop. JSON
  `additionalContext` supplies context and `decision: block` can continue
  work; exit 2 with stderr only warns. It can also read Claude settings,
  which does not make their exit meanings identical.
- **Cursor:** sessionStart, afterFileEdit and stop. It reads
  `additional_context`, `followup_message` and `user_message`; stop has a
  loop count and a five-continuation cap. It can import Claude settings,
  but needs its own output contract.

Profiles for Gemini CLI, Copilot CLI and Cursor are planned ideas. These and
other tools without a profile stay unwired until they have one. The commit
hook and team pipeline still apply to their work.
